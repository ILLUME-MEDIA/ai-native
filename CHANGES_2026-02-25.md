### 3.1 File Explorer Context Menu

**What it is:** Right-clicking any file or folder in the Explorer shows a context menu with: New File, New Folder, Rename (inline), Delete (with confirmation), Copy Path, Copy Relative Path.

**How it works:**
```
Right-click on file/folder
       │
Portal-rendered <div> at click coordinates (position: fixed, z-index: 9999)
       │
Menu items dispatch to:
  New File   → POST /files/create  { path, type: 'file' }
  New Folder → POST /files/create  { path, type: 'folder' }
  Rename     → Inline <input> replacing filename → PUT /files/rename
  Delete     → Confirmation modal → DELETE /files/delete
  Copy Path  → navigator.clipboard.writeText(absolutePath)
  Relative   → navigator.clipboard.writeText(relativePath)
```

**Files:** `FileExplorer.jsx`, `WorkspaceController.php`, `routes/api.php`

### 3.4 Outline Panel

**What it is:** The 4th activity bar item (≡). Shows all symbols (functions, classes, methods, variables) in the currently open file. Click a symbol to scroll the editor to that line.

**How it works:**
```
File opens in editor
       │
OutlinePanel queries Monaco's DocumentSymbolProviderRegistry
  If symbols returned → nested tree with kind badges
  If not (Monaco doesn't have a provider for this language)
  → Falls back to regex-based parsing:
      PHP:         function/class
      JS/JSX/TS:   function/const/class/interface
      Python:      def/class
      CSS/SCSS:    .selector / #id / @rule
       │
Click symbol → editor.revealLineInCenter(line)
                editor.setPosition({ lineNumber, column: 1 })
```

**Symbol badges:** F=Function · C=Class · M=Method · V=Variable · I=Interface · P=Property · E=Enum · K=Const

**Files:** `OutlinePanel.jsx` (new), `CodeEditor.jsx`, `_code-editor.scss`

### 3.5 Format on Save

**What it is:** On Ctrl+S, before writing the file, the content is sent to the backend formatter. If the formatter produces a different result, Monaco's content is updated before saving.

**How it works:**
```
Ctrl+S → handleSave()
       │
if editorSettings.formatOnSave !== false:
  POST /files/format { path, content }
       │
  Backend (WorkspaceController::formatFile):
    PHP:        vendor/bin/pint → vendor/bin/php-cs-fixer
    JS/JSX/TS:  node_modules/.bin/prettier → global prettier
    CSS/SCSS:   prettier with css/scss parser
    JSON/HTML:  prettier
    All via temp file in sys_get_temp_dir()
    Always returns { success: true, content: formatted|original }
       │
  If formatted !== original:
    monaco.setValue(formatted)
    monaco.setPosition(pos)  ← cursor preserved
       │
POST /files/write { path, finalContent }
```

**Files:** `WorkspaceController.php`, `routes/api.php`, `CodeEditor.jsx`

### 3.15 Merge Conflict Resolution

**What it is:** When a file contains git merge conflict markers (`<<<<<<<` / `=======` / `>>>>>>>`), a warning banner appears above the editor. Clicking "Resolve →" opens a dedicated conflict resolution view.

**Layout:**
```
┌──────────────────────────────────────────────────────────────┐
│ ⚠ 2 merge conflicts in this file                [Resolve →] │
├──────────────────────────────────────────────────────────────┤
│ CONFLICT 1 of 2                    ████████░░░░░░  1/2 done  │
│ ┌─────────────────────────────────────────────────────────┐  │
│ │ CURRENT (HEAD)                              [Accept]    │  │
│ │   return <LoginForm />;                                  │  │
│ ├─────────────────────────────────────────────────────────┤  │
│ │               [Accept Both]                              │  │
│ ├─────────────────────────────────────────────────────────┤  │
│ │ INCOMING (feature/auth)                     [Accept]    │  │
│ │   return <AuthProvider><LoginForm /></AuthProvider>;     │  │
│ └─────────────────────────────────────────────────────────┘  │
│                                          [Apply All]         │
```

**How it works:**
```
parseConflicts(content):
  regex: /<<<<<<<[\s\S]*?=======[\s\S]*?>>>>>>>/gm
  returns: [{ full, startIdx, currentLabel, current, incomingLabel, incoming }]

applyResolutions(content, conflicts, resolutions):
  processes conflicts in reverse order (by startIdx)
  replaces each conflict block with the chosen content
  preserves all surrounding text exactly
```

**Files:** `MergeConflictPanel.jsx` (new), `CodeEditor.jsx`

### 3.18 AI Inline Ghost Text

**What it is:** As you type, the AI suggests completions as grey ghost text (like GitHub Copilot). Press Tab to accept, Esc to dismiss. Toggle with the ⚡ icon in the status bar.

**How it works:**
```
User stops typing for 800ms
       │
Monaco InlineCompletionsProvider fires:
  POST /ai/complete {
    path:    "src/App.jsx",
    content: "<full file content>",
    line:    45,
    column:  28
  }
       │
Backend builds context:
  - last 40 lines before cursor
  - current line up to cursor position
  - 8 lines after cursor
  Prompt: "Return ONLY the text to insert at <cursor>..."
       │
Response: { completion: "useState(null)" }
       │
Monaco renders as inline grey text
Tab → accepts, inserts completion
Esc → dismisses
```

**Status bar toggle:** ⚡ icon (orange = enabled, dim = disabled). Persists to `localStorage ce.ghostText`.

**Files:** `MonacoEditor.jsx`, `AICommandController.php`, `routes/api.php`, `CodeEditor.jsx`

### 3.21 Presence / Collaboration Indicators

**What it is:** Colored avatar circles in the status bar showing which team members are currently viewing the same workspace. Hover to see their name and which file they have open. White border = same file as you.

**Implementation (polling — no WebSocket needed):**
```
On workspace open:
  POST /presence/heartbeat every 12 seconds
    { open_file: "/src/App.jsx" }

UI polls GET /presence every 15 seconds
  returns: [{ user_id, name, open_file, last_seen }]

### 3.22 Visual Editor

**What it is:** Click the 🖌 Paintbrush icon in the activity bar to switch to Visual Editor mode. The active HTML/CSS/SCSS file renders in a live iframe. Click any element — a properties panel appears on the right showing its computed CSS. Edit properties and click "Apply to Source" to write a CSS rule back to the file.

**How it works:**
```

       │

  mouseover → draws orange highlight overlay on hovered element
  click     → e.preventDefault() + postMessage to parent:
    {
      type: 'VISUAL_EDITOR_ELEMENT_SELECTED',
      selector: '#hero > h1.title',
      tagName: 'h1',
      styles: { display, position, fontSize, color, margin... },
      rect: { top, left, width, height }
    }
       │
React parent receives postMessage → shows properties panel
       │
Properties panel — 3 tabs:
  Layout:     display (flex controls), position, width, height,

User edits values → "Apply to Source":
  Computes changed properties only
